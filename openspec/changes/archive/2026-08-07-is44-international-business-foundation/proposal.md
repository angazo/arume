## Why

Arume va a comenzar la lógica de negocio y necesita demostrar desde el primer dominio funcional que el núcleo puede permanecer independiente de la normativa de cada país. El primer vertical debe establecer una base común para empresas y ejercicios fiscales, y aislar en un módulo español las series de facturación, evitando que la futura internacionalización dependa de refactorizaciones posteriores.

## What Changes

- Crear el módulo Gradle `arume-core` como núcleo de dominio y casos de uso independiente de Spring, MyBatis, JavaFX y cualquier país.
- Crear el módulo Gradle `arume-es` para las reglas y persistencia específicas de España.
- Introducir la gestión de empresas, diferenciando identidad fiscal estructural de datos evolutivos con histórico.
- Mantener inmutables el código de identificación fiscal principal y la forma jurídica de una empresa durante su vida fiscal.
- Introducir ejercicios fiscales independientes, con fechas explícitas y soporte para ejercicios cortos.
- Introducir series de facturación españolas pertenecientes a una empresa, con configuración y estado de numeración por ejercicio fiscal.
- Definir capacidades fiscales mediante contratos pequeños y resolver los módulos nacionales mediante registro o factoría, sin condicionales de país en el core.
- Añadir una pantalla temporal de Empresas para listar y crear empresas.
- Establecer el contrato de compatibilidad entre el esquema core y los módulos nacionales.
- Investigar y dejar definida la estrategia de migraciones core y nacionales, incluyendo el orden core → país y las claves foráneas entre ambos espacios.

## Fuera de alcance

- Migrar la base de datos actual; durante este change la aplicación se inicializará desde cero sobre una base nueva.

## Capabilities

### New Capabilities

- `company-management`: creación, listado y ciclo de vida de empresas con identidad fiscal estructural y datos evolutivos.
- `fiscal-year-management`: creación y gestión de ejercicios fiscales asociados a empresas.
- `spain-invoice-series`: configuración de series de facturación españolas y su estado por ejercicio fiscal.
- `international-module-architecture`: separación del core y módulos nacionales, contratos de capacidades fiscales y compatibilidad entre esquemas.

### Modified Capabilities

- Ninguna.

## Impact

- Nuevos módulos Gradle `arume-core` y `arume-es`.
- Refactorización de `arume-db` para actuar como adaptador de persistencia del dominio común, manteniendo los modelos generados de MyBatis fuera del dominio.
- Nuevos contratos de dominio, casos de uso, repositorios y adaptadores de persistencia.
- Nueva migración o conjunto de migraciones para tablas core y tablas españolas con prefijo `es<n>_`.
- Nuevos controladores y vistas JavaFX para la pantalla temporal de Empresas.
- Revisión de la configuración de Spring, el escaneo de mappers y la composición de migraciones Flyway.
- Las PK internas de las entidades de negocio serán `BIGINT GENERATED BY DEFAULT AS IDENTITY`; la aplicación no generará esos IDs.
- Actualización de pruebas unitarias, de integración con H2/Flyway y de interfaz JavaFX según corresponda.
